# A23 开发规格

## 交付范围

六周挑战档覆盖四种文档、多源候选归并、两种模板填写、逐格追溯和可复现验收。原赛题模块一现有自然语言操作首版，支持受控 DOCX 与 XLSX 编辑、排版及提取。空气质量 Word 模板、03 形态目标 XLSX 和异步抽取已有首版；通用模板与比赛样本评测仍按竞赛扩展规划推进。[六周总规划](../六周任务/两档难度总规划.md) · [A23 赛题](../六周任务/第十七届服务外包比赛A23赛题.md)

## 技术栈

| 部分 | 技术与约束 |
| --- | --- |
| 后端 | Python 3.14 项目内 `.venv/`，FastAPI、Pydantic、Uvicorn，接口以 `backend/main.py` 为入口 |
| 数据 | Python 标准库 `sqlite3`，数据库默认位于 `backend/data/a23.db` |
| 文档 | TXT、Markdown 按 UTF-8 解码并接受 BOM，DOCX 使用 python-docx，XLSX 使用 openpyxl |
| 模型 | httpx 调用 DeepSeek Chat Completions，使用 `deepseek-flash`、temperature 0、JSON 输出、60 秒请求超时。密钥读取 `DEEPSEEK_API_KEY`，支持 `backend/.env` |
| 前端 | Vue 3、Vite、JavaScript、浏览器原生 fetch。使用现有 Node.js 和 npm，FastAPI 同源托管构建产物 |
| 验收 | pytest、FastAPI TestClient、合成参考表评分与公开样本原文核对。在线抽取由命令或交互显式发起 |

## 代码风格

Python 用 4 空格缩进，文件、函数和变量用 `snake_case`，类型用 `PascalCase`，模块常量用 `UPPER_SNAKE_CASE`。模块边界补全参数和返回类型。Vue 使用单文件组件与 `<script setup>`，JavaScript 用 2 空格缩进，函数和响应式变量用 `camelCase`。注释说明业务判据、单位或顺序的原因。用户可见提示用中文，接口字段沿用任务书。

同一条规则只定义一次。HTTP 层负责参数校验和错误转换，SQL 在存储层用参数占位符。路径从模块或指定数据目录计算，支持中文文件名。模板另存为输出，评估参考答案只经评估模块读取。等待模型时避免持有数据库写事务，所有批次成功后按 `doc + mode` 事务替换事实。

## 功能与验收

| 功能 | 实现与检查 |
| --- | --- |
| 文档解析 | `POST /parse` 接收四种格式并返回 `file` 和 `blocks`。TXT、MD 跳空行且保留原行号。DOCX 保持段落与表格顺序，为段落和实际单元格分配独立定位。XLSX 只读流式遍历，块文本保留列名，跳过全空行。坏文件或未知后缀给出可读错误。[第 2 周](../六周任务/第二周任务.md) |
| 自然语言操作 | `POST /operations/preview` 从 DOCX/XLSX 和中文指令生成结构化列表，校验段落、工作表、单元格和原话并展示预期结果。确认后 `POST /operations` 用原文件及计划 ID 执行，校验文件名与内容摘要；仅全部成功时发布副本。提取返回连续原文与位置，下载走 `GET /operations/files/{result_id}`。计划和结果在单进程内暂存 30 分钟。模型输出只可调用预定义操作。[模块一要求](../六周任务/第十七届服务外包比赛A23赛题.md) |
| 事实抽取 | `POST /extract` 接收 `file` 与逗号分隔的 `metrics`，支持通用和清单模式，返回 `doc, mode, count, kept, rejected, classification`。分类契约版本 1 仅对文件格式、解析块和已保留事实的值类型做规则统计；`semantic_category=null` 表示尚无正式语义类别。块号必须在当前批，原话须为对应原文的连续片段，数值须能在原话中核对。保留原始指标与单位，入库另存归并键、期次和出处。XLSX 解析完整入库，发送模型的行数受单独的抽取上限约束。[第 3 周](../六周任务/第三周任务.md) |
| 异步识别与计时 | `POST /tasks` 返回任务 ID，`GET /tasks/{task_id}` 返回状态、原文件摘要、当前发布摘要、结果或定位到批次和块的错误。同名同步与异步请求按登记顺序发布，旧请求晚完成为 `superseded`；事实和成功状态同一事务提交。`timing_capture.py` 记录客户端首响、轮询终态、服务端排队与运行时长，可选固定模板填写与下载请求。该计时不等同赛题正式五模板计时。[README](../README.md#用自己的材料) |
| 多源归并 | 按主体、显式归并指标、期次和统计口径对齐候选。期次从数值所在分句或紧邻标题确定，必要时查同句最大年份并继承上文标题。同键异值且无明确指定来源时保留候选并拒填。调用 `POST /facts/decisions` 可以保存采用项、候选、原文摘要与理由，`GET /facts/decisions/{decision_id}` 读取历史快照。[第 3 周](../六周任务/第三周任务.md) |
| 01 城市经济模板 | 依据原文正文顺序定位城市，按目标年份、全年口径、四项指标及单位写入 B–E 列。年月归属不明且存在多期候选时留空。公开标题明确 2025 年，`/fill` 可对其他城市材料显式给 `target_period`。正式形状要求 100 个不同城市，逐格记录含选中事实、期次、口径、模式。评分按 A2:E101 比较并拒绝缺少有效应填值的参考表。[第 4 周](../六周任务/第四周任务.md) |
| 03 历史疫情统计模板 | 2020-07-01 至 2020-08-31，日期升序，同日国家名升序。仅从匹配日期和国家统计口径的结构化数据写值，地区叙述保留作范围判断依据。逐格记录填写或拒填原因，日期写 Excel 日期，缺值保留为真空。正式验收为 2542 行 × 7 列，应填 17464 格、应空 330 格，分别计算对格率、误填率和漏填率。[第 4 周](../六周任务/第四周任务.md) |
| 填写与演示 | `POST /fill` 接收文档名、模板名与可选原文摘要，JSON 仍返回 `rows, cells_written, cells_empty`，响应头提供内容标识和服务端填写耗时。配置 `A23_REFERENCE_DIR` 时读取该目录的 `参考_01.xlsx` 或 `参考_03.xlsx` 生成评分。配置 `A23_SOURCE_CHECK_ROOT` 时，字节匹配的公开样本可生成独立原文核对报告。`GET /reports` 只读本次批次与工作簿摘要匹配的报告。`GET /files` 仅下载 `filled_*.xlsx`，页面下载附结果标识。`GET /cells` 是两套场景共用的追溯入口。[第 5 周](../六周任务/第五周任务.md) |
| 回归与交接 | 同库复验按精确值判定。历史重建与在线重建分别核对初始空库、最终数据库、事实归档或原始响应及填写批次。比较成对样本时核对同源同模板、不同库摘要。重建使用归档支持的区间，保留全部差异。综合验收要求前端已构建。[第 6 周](../六周任务/第六周任务.md) |

任务书的固定块数、行数和分母仅适用于指定样本。合成样例用于检查解析、证据校验、候选冲突、真空与零、填表、比对和接口。正式验收需要原始输入、模板、参考结果、本地密钥，以及可核对的真实运行记录。

运行模型由任务书的 `deepseek-chat` 更新为 `deepseek-flash`。真实抽取的验收记录需注明模型名，重建库复验的区间须依据该模型的实测数据。[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)

## 实测记录

本轮在 macOS Apple Silicon 独立 Clone 和新虚拟环境中完成构建、测试、01 预置库与 03 空库的 Chrome 演示。真实 TXT 两轮的模型响应、过滤差异和重放结果已保存。两份历史城市抽取分别用于同库与重建原文核对，正式参考表和 Windows 实机结果仍待补。[六周验收记录](六周验收记录.md)

实验日志记录源文本的原始模型响应，保存在 CLI 指定数据目录下的 `extraction-runs/`。提示词保存摘要。日志与报告均使用本地文件，HTTP 抽取端点只返回本次的汇总计数。SQLite 写入由 `Store.save` 事务处理。Web 进程内串行填写以保护固定输出文件，隔离验证和命令行评分使用独立数据目录。

配置的参考表不可用时，填写仍返回可以下载的结果。评分异常写入服务日志，HTTP 响应头 `X-A23-Score-Status: failed` 供工作台显示自检错误。缺少当前版本评分时 `GET /reports` 返回 404。

### 01 字段映射

| 原文指标或常见说法 | 输出字段 | 列 | 可用单位 | 系数 |
| --- | --- | --- | --- | ---: |
| GDP 总量、地区生产总值、GDP | GDP总量（亿元） | B | 亿元 | 1 |
| 常住人口、人口基数、人口严控至、万人口 | 常住人口（万） | C | 万、万人、万人口 | 1 |
| 人均 GDP、人均地区生产总值、人均生产总值 | 人均GDP（元） | D | 元、元/人 | 1 |
| 一般公共预算收入、公共预算收入 | 一般公共预算收入（亿元） | E | 亿元 | 1 |

代码定义在 `fill_spec.CITY_COLUMNS` 和 `METRIC_ALIASES`。01 写表前用 `city_claim` 核对原文里数值的指标和含义，包括数值在指标之前的写法。净增、同比增减量、增速和比率无法填入总量或水平字段。原文明确写「从 90 亿元增长至 100 亿元」时，100 是可用的绝对终值，起点和普通区间端点会拒填。

01 实绩字段在比较候选前，按原文数值所在表达排除目标和预测。只取得目标或预测时，逐格报告分别给出 `goal` 或 `forecast`，保留候选引用。已发布的初步核算值可参加实绩判断。

「目标值」「预测值」可位于数值后面，同组并列指标会继承上文的「预计」语气，后项明确「实际」时结束继承。无关的「预测值仅作比较」附注不改变外侧实际数值角色。

季度、半年、月份范围或含日的截止日期约束同一报告句中相关的并列指标，可经过「初步核算」等中性分句延续。句末、分号及明确不同年份可结束该范围，「全年」等明确口径由相应数值采用。括号中另列的子值或数据发布说明保留各自语境，单独注明统计口径的括号仍用于约束该值。明确年份下未注明更细口径的正文数值按年度候选处理。部分周期即使被模型标为全年也会拒填。逐格报告保留原话、原文位置和检出的 `source_scope`。

指标前或指标后明确写出的年份都参与同组截止口径切换。「经初步核算口径调整后」作为报告插语保留前述截止范围。
