# 第一周任务
这一次我们希望全体成员都可以体验到完整的软件制作流程，因此在任务难度上我们不会直接采用赛题原本的难度，而是会稍作修改，这一点在第二周的文件中会详细说明的    
那第一周的时候需要我们做什么呢？  
从零基础开发的角度，首先从python下载开始  
1、你需要在自己的电脑上下载好python的解释器<https://www.python.org/>，我们建议你选择稳定的版本（更好的方案：  
我们很有可能会在电脑中安装许多个版本的python，为了解决这个问题，我们通常可以下载conda<https://www.anaconda.com/download>进行管理，conda分为anaconda和miniconda，我们建议选择miniconda，conda在环境管理等方面相较于python自带的虚拟环境同样更好用）**记得配置好环境变量**（同样值得说明的是uv也是一个python环境管理器，与conda相同，你也可以使用它）。这里说明一下「环境变量」到底是什么：系统的 PATH 环境变量是一份「系统认识哪些命令」的清单，只有把 python 的安装位置加进去，你在终端敲 python 它才认识。最省事的配法是在安装时勾选——python 官方安装器勾选 Add python.exe to PATH，miniconda 安装器勾选 Add Miniconda3 to my PATH。装完后**务必验证**：重新打开一个终端（Win+R 输入 cmd 回车），运行 `python -V`，显示版本号才算成功（注意：如果终端是安装之前就开着的，要关掉重开，否则读到的是旧配置）  
2、在自己电脑上建立一个代码文件夹并创建一个python虚拟环境（虚拟环境的作用是为不同项目隔离运行环境）。代码文件夹建议建在 D 盘等非系统盘，用英文名（如 D:\code\a23-project），**路径里不要有中文和空格**——这是很多诡异报错的源头。创建虚拟环境的命令二选一：  
- conda 方式：终端运行 `conda create -n a23 python=3.11`，创建后运行 `conda activate a23` 激活  
- python 自带方式：在代码文件夹里运行 `python -m venv .venv`，然后按你用的终端激活：cmd 用 `.venv\Scripts\activate`；PowerShell 用 `.venv\Scripts\Activate.ps1`（若提示「禁止运行脚本」，先执行一次 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`）；Git Bash 用 `source .venv/Scripts/activate`  
激活成功的标志：命令行提示符最前面出现环境名，比如 (a23) 或 (.venv)。以后每次打开终端准备干活，第一件事就是激活它  
3、在自己的电脑上下载git（git是一个分布式版本控制系统，可以帮助你管理自己的代码）。安装过程基本一路 Next、保持默认选项即可。装完验证：终端运行 `git --version`，显示版本号即成功  
4、配置好git并注册一个gitee账号（gitee与github都是基于git开发的代码托管网站，他们的作用就是将你本地的代码托管到云端，让你的团队可以协同作战，github是一个全球的现象级的代码托管平台，上面有无数开源项目，强烈建议大家如果可以多逛逛该网站，但是gitee作为国内的托管平台对于大家来说更易访问，也更加稳定，所以这次我们选择gitee）。注册完 gitee 后，还需要给 git 配置你的身份（作用是给每一次提交署名，不配置的话第一次提交就会报错），在终端运行两条命令：  
`git config --global user.name "你的名字"`  
`git config --global user.email "你的邮箱"`（建议和 gitee 的注册邮箱一致）  
5、将代码文件夹进行git初始化：用 vscode 打开你的代码文件夹，在它的终端里运行 `git init`。成功后文件夹里会多出一个隐藏的 .git 目录——它是这个仓库的「记忆」，**千万不要删它**  
6、下载vscode（我们建议你使用vscode进行开发，当然python项目同样可以使用pycharm软件进行开发），配置为简体中文，你需要下载好扩展（这一点不着急做，缺什么插件下就是了），同样你可以看到vscode中集成了git，这意味着你可以使用可视化面板进行git操作，而不是命令行         
7、为了让你们更好使用AI，需要在vscode中下载一个叫做deepseek V4 for copilot chat的扩展，它可以让你在vscode中使用deepseek模型，然后你需要去deepseek的官网上生成一个API Key（**切记API Key不得告诉他人，使用应该专一，一个Key只能使用在一个位置，不小心暴露，立马删除！**），在vscode中按住ctrl+shift+p打开命令面板，并输入deepseek:set API Key，在里面输入你刚刚粘贴的API Key。现在你可以在vscode中使用deepseek为你解释代码，生成代码了。**注意切记不可滥用AI！**  
8、学会在vscode中打开文件夹，并且学会查看和编辑markdown文件（打开一个 .md 文件后，按 Ctrl+Shift+V 可以预览排版效果）  
9、下载nodejs（选 LTS 长期支持版本），它的安装器默认就会帮你配好环境变量。装完重新打开终端验证：`node -v` 和 `npm -v` 都能显示版本号（nodejs 是 Vue 前端的运行环境，Vue 项目靠它的 npm 工具安装依赖）  
10、上传你的本地仓库到gitee，分三步：  
① 在 gitee 网页上点「新建仓库」，填仓库名（建议和本地文件夹同名），**不要勾选**「使用Readme文件初始化这个仓库」——两边都有初始提交会导致历史不一致，push 会被拒绝  
② 回到本地终端，依次运行四条命令：  
`git add .`（暂存所有改动）  
`git commit -m "第一周：初始化仓库"`（提交，引号里是本次提交的说明）  
`git remote add origin 你的仓库地址`（关联远程仓库，地址在 gitee 仓库页面顶部，选 HTTPS 那个）  
`git push -u origin master`（推送。如果提示找不到 master 分支，说明你的默认分支叫 main，把命令里的 master 改成 main 再执行）  
③ 以后每次提交代码只需要三步：`git add .` → `git commit -m "这次做了什么"` → `git push`。这个流程在接下来六周里你会重复上百次，第二周开始它就是肌肉记忆
  
## 以上都是些基本操作，接下来才是这一周的重点：
1、你需要熟悉git，知道git clone、git  push、git add等命令，且知道如何暂存你的代码，提交你的代码，知道如何推送你的代码到远程仓库。你需要知道.gitignore文件是用来做什么的，并且学会配置它。.gitignore 的作用是告诉 git「这些文件不用跟踪」——像虚拟环境（.venv/）、前端依赖（node_modules/）动辄几千上万个文件，一旦提交会严重污染仓库。建议你本周就在 .gitignore 里写入以下内容（每行一条）：  
.venv/  
__pycache__/  
node_modules/  
2、你需要知道如何编辑markdown文件，markdown文件是程序员常用的文件形式（它是一种纯文本的排版格式：用 # 表示标题、用 - 表示列表、用三个反引号表示代码块，你正在读的这份文档就是用 markdown 写的。程序员用它写文档和 README，因为纯文本、好维护、git 能清晰追踪它的每一次修改）。  
3、你需要访问fastapi和vue的官方网站，并且知道如何下载他们，配置好你的代码文件夹（先混个脸熟即可：fastapi 是一个 Python 的 Web 服务框架，作用是把你写的函数变成可以通过网址调用的「接口」，第二周会正式使用它；vue 是一个前端框架，用来编写网页界面，第五周会正式使用它。这周不用装；第二周装 FastAPI 时统一用 `python -m pip install "fastapi[standard]"`，**即使用 conda 建的环境也用它**——`conda install -c conda-forge fastapi` 装出来的是 2023 年的旧版本，缺 uvicorn、fastapi-cli 等依赖，照它做第二周会走不通，原因第二周会讲）  
4、你需要熟悉Python的语法，至少知道Python的数据结构、循环、条件等怎么写，不建议在细枝末节处停留过多时间，真正的熟悉只能靠敲代码锻炼出来，你可以参考<https://www.runoob.com/python/python-tutorial.html>

# 第一周提交结果
1、你需要提交一个公开的gitee仓库的地址，仓库里面必须有：  
README.md 文件（文件名照此大小写写，与下方目录结构里的名字保持一致），里面需要记录以下信息：python -V、git --version、node -v、npm -v（这些命令需要在你的电脑的终端中运行）  
2、仓库中需要看到你的目录结构，示例如下：  
a23-project/  
├── backend/  
│   └── .gitkeep      # 占位文件，作用见下方说明  
├── frontend/  
│   └── .gitkeep  
├── README.md  
└── .gitignore

**注意一个 git 的常识：git 只跟踪文件，不跟踪空文件夹。**如果你只是把 backend/ 和 frontend/ 两个空文件夹建在那里，add、commit、push 之后打开 gitee 网页，会发现这两个文件夹根本没上去——这是几乎每个人都会踩的坑。解决办法是一个业界惯例：在空文件夹里放一个叫 `.gitkeep` 的空文件。它没有任何特殊功能，就是占个位置，让文件夹「不空」，git 就愿意跟踪它了（在文件夹里新建一个文本文件，把文件名连同后缀一起改成 `.gitkeep` 即可）。等以后文件夹里有了真实代码，可以把 `.gitkeep` 删掉。

# 卡住怎么办
1、环境配置类问题（安装失败、命令找不到、权限报错）：完整复制报错信息，先自己搜索，再把报错贴给 AI 问「这个报错是什么意思、怎么解决」。90% 的环境问题前人都踩过，能搜到答案
2、概念类问题（不懂虚拟环境是什么、git 的三个区是什么）：先问 AI「用大白话解释 XX」，再回到任务继续
3、30 分钟无进展：把「你在做什么、报错是什么、你试过什么」三句话整理好，继续与 AI 多轮排查（换个问法、贴上完整上下文，往往就通了）
4、记住本周最重要的一个安全习惯：**API Key 不得告诉他人，不得提交进仓库，不小心暴露立刻删除重建**
