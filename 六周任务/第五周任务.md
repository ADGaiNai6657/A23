## 二、本周仓库要长出的结构

上周结束时，`backend/` 里站着十三个 `.py`（按入仓文件计，不含被 `.gitignore` 挡住的 `check.py`，也不含第 2 周二档自定的解析器——文件名不同，职责不变），`data/` 下有 `a23.db`、`parse_result.json`、`facts_export.json`、`filled_2025中国城市经济百强.xlsx`、`fill_report.json`、`eval_report.json`（第 4 周走完 01 链路时的状态；第二档同学另有三份 covid 产出，不影响本周）。只做到第 4 周最低完成线、没生成 `eval_report.json` 的，第一档第 0 步会让你回补。三个接口 `/parse`、`/extract`、`/fill` 都能用，但只能从 `/docs` 里点、或从脚本里调；`frontend/` 里还只有第 1 周留下的那个 `.gitkeep`。

脚手架还会生成一批示例内容：一个欢迎页组件、一个 logo、几段示例样式。这些本周一律删掉或清空——页面上留着一张"Welcome"卡片，会让评审分不清哪些是你写的。

哪些留、哪些删，按这张表办（文件名以你本地生成为准，行为不变）：

| 做法 | 对象 | 理由 |
| --- | --- | --- |
| 重写 | `src/App.vue` | 本周的页面就从这里开始，示例内容整段替换掉 |
| 保留 | `index.html`、`package.json`、`vite.config.js`、`src/main.js` | 入口与构建配置，动了就起不来 |
| 保留 | `src/` 里被 `main.js` import 的那个样式文件（各版本可能叫 `main.css`、`style.css` 或 `base.css`） | 删了会白屏；文件名不同不算错，认 `main.js` 的 import 那行 |
| 删除 | 示例组件目录（`src/components/`）、logo、示例样式里没用到的段落 | 留着会在搜索与验收时误导人 |
| 可留可删 | `public/`、`.vscode/`、`jsconfig.json` | 不影响运行，也不占篇幅 |

关于"多出一个 Vite"这件事，先说明白：**Vite 是构建工具，不是框架，也不是运行库。** 它只在 `npm run build` 那一下出现，把 `.vue` 文件编译成浏览器能读的 `.js`，产物是纯静态文件；页面在浏览器里跑的是 Vue 本体，没有第二个框架。总规划排掉的是前端工程化那三项（路由、状态管理、组件库选型），构建工具不在其列。本周只用它做编译这一件事：不装路由、不装状态管理、不装组件库、不装 CSS 框架、不装 axios（请求用浏览器自带 `fetch`）。

这棵树按脚手架默认产物画；第 3 步会真的建一次，建完按你本地的实际产物对照，文件名不同以本地为准——名字可以不一样，行为不能：入口是一个 `index.html`、挂载点在 `src/main.js`、页面组件是 `src/App.vue`、样式由 `main.js` import。

`/health` 是三者里唯一"没有业务含义"的：它不读库、不读报告，只回一个固定值，页面用它判断后端在不在（第一档第 5 步那行后端状态会用到）。

各路径的职责（每个文件只干一件事）：

| 路径 | 职责 | 不该做的事 |
| --- | --- | --- |
| `main.py` | 收请求、调已有函数、返回 JSON；末尾把 `frontend/dist` 挂到 `/` | 不内联列号、不重算准确率、不写业务逻辑 |
| `check_fill.py` | 跑填写与比对、打印数字；报告的外层按需整理，数值不改 | 不为界面重算两个率，不改比对规则 |
| `store.py` | 按块号取一块原文（第一档用不到，第二档才要） | 不拼前端路径、不返回整张表 |
| `api.js` | 把三个接口包成几个函数，统一处理错误 | 不写页面逻辑、不拼 HTML |
| `App.vue` | 页面长什么样、什么时候显示什么 | 不写 `fetch`、不拼接口地址 |
| `src/assets/` 里的样式 | 少量样式 | 不引外部 CSS 框架 |
| `frontend/dist/` | `npm run build` 的产物，由后端托管 | 不进仓库，不手改里面的文件 |

三条约定，后面几节都要用：

1. **前端不碰 `data/`，只认接口。** 浏览器读不到你磁盘上的 `eval_report.json`，也不该读到——页面上每一个数字都必须经由后端返回。这条同时挡住另一种走法：把 JSON 复制进 `frontend/public/` 假装"页面能显示"。那种页面在第 6 周换台机器后一定是空的，因为它显示的是拷贝那一刻的快照。
2. **这周只动"读"，不动"算"。** `/reports` 把第 4 周已经算好、已经落进 `eval_report.json` 的两个率读出来，`/files` 把已经生成的表发出去；`evaluate.py` 的比对规则、`filler.py` 的写入方式、两个率的算法，一行不改。唯一允许动的是那份报告的外层形状（第 4 周目录说明要求它"含两个率"，正文只规定了清单里每条有什么）：外层从数组变成对象可以，里面的数值一个不能变。数在界面上变了，说明改坏了东西，不是改好了。
3. **页面只有一个地址。** `npm run build` 出 `dist`，后端把 `dist` 挂在 `/` 下，浏览器只打开 `http://127.0.0.1:8000`。不起第二个服务、不配代理、不处理跨域——同源就没有跨域这回事。代价是改完前端要重新 build 一次，第一档第 8 步会把这条写成检查点。

两条位置要求：`frontend/` 与 `backend/` 同级，别塞进 `backend/` 里面，否则 build 出来的相对路径对不上；`dist` 由 build 生成，不要手工拷贝、也不要提交进仓库——第 6 周别人按 README 跑一次 `npm install` 加 `npm run build` 就能得到同样的东西，提交进去反而会让"这份 dist 是哪次改动的"说不清。

三条命令的执行位置与顺序：创建项目在仓库根执行、项目名填 `frontend`；之后 `npm install`、`npm run build` 都在 `frontend/` 里执行，顺序也是这个顺序——装依赖、再构建、最后才启动后端（`dist` 不存在时后端起不来，第 4 步会说）。站错目录时，报错是 `ENOENT: no such file or directory, open ...package.json`，看着像环境坏了，其实只是位置不对。`package-lock.json` 要提交——它锁住依赖版本，第 6 周别人装出来的才和你一样；`node_modules/` 不提交。

还有一件与"简单"有关的事要提前说死：**本周不用脚手架自带的开发服务器（`npm run dev`）。** 它跑在另一个端口（Vite 默认 5173），而接口在 8000；页面上的请求会打到 5173，拿回一段 HTML，再在解析 JSON 时失败，报错信息与真正的原因差着十万八千里。这周的走法是"build 一次，从 8000 看"，只有一条路。

还有一处要提前确认：第 1 周写进 `.gitignore` 的 `node_modules/` 还在，第 4 周按六条确认过它。脚手架会在 `frontend/` 下再生成一份 `.gitignore`（其中含 `node_modules` 与 `dist`），两份并存不冲突；验收标准只有一条——`git status` 里看不到 `frontend/node_modules` 与 `frontend/dist`。查两次，不是一次：`npm install` 之后查一次（挡 `node_modules`），`npm run build` 之后查一次（挡 `dist`）——`dist` 是构建时才出现的，装完依赖那会儿它还不在，那时查不到不代表以后挡得住。不确定有没有被挡住，两条各查一次：`git check-ignore -v frontend/node_modules` 与 `git check-ignore -v frontend/dist`，两条都要有输出——它会告诉你命中的是哪份文件的哪一行。`dist` 那条尤其别漏：它 build 之后才出现，而提交时最容易发现不了的就是它。

真要补规则时，加在文件末尾，别用 `git rm --cached` 去救已经加进来的文件——那只是取消跟踪，历史里还在。若两份 `.gitignore` 里都没有 `dist`，在仓库根那份末尾补一行 `dist/`：这一条能同时挡住各级目录下同名的产物，比写 `frontend/dist` 更省事。`node_modules` 动辄上万个文件，一旦提交，仓库会大到没法 clone。

# 引导和说明：

上周结束的时候，我们手上有一份 101 行的 Excel、两个报得出来的率、两份能解释它们的 JSON。东西是齐的，但它只在两种场合出现：在终端里跑脚本，或者在 `/docs` 页面里点。把仓库地址发给别人，对方 clone 下来、装完依赖、起完服务，看到的是一份接口文档——你还得在旁边告诉他"先传这个文件，再点这个，然后看那个数"。

这周要把这条口头说明，换成对方自己点得出来的东西。

先别急着动手，把六周摊开看一眼，知道这周站在哪儿：

| 周             | 这周把什么变成什么                          |
| ------------- | ---------------------------------- |
| 第 1 周         | 环境与仓库：代码进得去仓库，别人看得懂                |
| 第 2 周         | 文件 → 统一数据：多格式进，一个 schema 出         |
| 第 3 周         | 文本 → 结构化事实：抽出事实，每条都说得出出处           |
| 第 4 周         | 数据 → 交付物：填进模板，并报得出可核对的数字           |
| **第 5 周（本周）** | **后端 → 能用：接上界面，整条链路能演示**            |
| 第 6 周         | 能跑 → 能交接：测试、复现、交给别人接手              |

这张表里有个转折值得说清：前四周你一直在做"里面"，本周第一次做"外面"。里面的东西讲得再清楚，外面的人也只能听你讲；而比赛要交的是能演示的程序，第 6 周要交的是别人能接手的东西，两者都得先有一张别人打得开的页面。所以这周不是"顺手做个界面"，是把前四周的成果**变成可被他人使用的形态**。

那这周具体干什么？一句话：**给已经能跑的后端，接上一个打开浏览器就能走完的页面。**

可以先想一个场景。评审拿到你的仓库，按 README 起服务，打开一个地址。页面上写着"选择一份文档"，他选了一份，点"开始"。几秒后，页面上出现四行数字：行数 100、写入格数 500、空着的格数 0、耗时 1.8 秒；下面还有两个率，和一个"下载填好的表"的按钮（都是示意，实际以你自己的输出为准）。他不需要知道你用了什么模型、提示词改了几遍，也不需要读你的代码——他已经看见这件事成了。

这就是这周要交的东西。它的价值不在好看，在**别人不用问你就能自己走一遍**。

这周有个新情况，值得单独说：**错误的藏身之处换了地方。**

前三周出错，终端里大多会给你一行红字，有文件名、有行号；第 4 周已经出现过另一种——程序跑完不报错，数字却是错的。这周两种都会遇上，而线索不都在终端里：页面点下去没反应，终端里什么都没有——因为请求根本没发出去，或者发出去了但字段名拼错了。真正的线索在浏览器的开发者工具里，按 F12 打开，切到 Console 与 Network 两个面板。Console 里是 JS 的报错和你自己打的日志；Network 里是每一次请求的地址、状态码、返回内容。**这两个面板不看，这周的卡点基本只能靠猜；会看，多数问题当场就能定位。**

还有一件事和第 4 周同源：**前端不会替你检查字段名。** 后端返回 `cells_written`，你写成 `cellsWrite`，程序不报错，页面上那个位置就是空的。第 4 周管这叫"静默错误"，这周它换了个样子又来了。所以本周每一步的"做完你应该看到"，都要真的去页面上看那行字有没有出现，而不是"代码写完了就算完"。

**本周只有一个新概念：响应式。**

说清楚就一句话：**页面不是你去改的，是你描述"数据长这样时界面该长这样"，数据一变，界面自己跟着变。**

对比一下前四周的写法就明白了。第 2 周你写 `print(len(doc.blocks))`，数字变了要重新跑一次才看得到；这周你在页面里写 `{{ blockCount }}`，只要 `blockCount` 这个值被赋了新数，页面上的字立刻跟着变，你不用碰 DOM、不用 `document.querySelector`、不用 `innerHTML`。三个东西够用一整周：一个变量（`ref`）、一个循环（`v-for`，把一串错格渲染成表格）、一个条件（`v-if`，加载中显示"处理中"，失败显示原因）。

听上去像魔法，代价是它只对"被 Vue 管着的变量"生效：你在函数里 `let count = 0` 再改它，页面不会有任何反应。这类"改了但没变"的空白，是这周最常见的卡点，「卡住怎么办」第 2 条专门讲。

至于接口怎么调、页面怎么排版，都不算新概念：`fetch` 做的事和第 2 周你在 `/docs` 里点的那一下是同一件事，只是调用方从人换成了 JS。

这周真正要你自己拿主意的地方，是**一条链怎么摆**：解析、抽取、填表、看报告，四件事是排成一条竖线一路点下去，还是分成两块各管各的；抽取要等模型回话、一次跑下来不短，是放进"一键演示"里让人干等，还是单独一个按钮、演示时跳过；加载中、成功、失败三种状态各显示什么，按钮要不要禁用。这些没有唯一答案：第一档第 7、8 步只规定页面上必须出现什么、哪些情况必须说清楚，怎么摆由你定。

**这周不做什么。** 记住一句就够：这周只负责"让已有的东西被人用起来"，不负责"把系统做大"。不加登录、不加路由（页面就一个，不需要多页跳转）、不加状态管理库、不引组件库和 CSS 框架、不做移动端适配、不做部署上线——总规划里这几条本来就写着不做。也不重修后端：`/parse`、`/extract`、`/fill` 的返回结构一个字不改，界面去适配它们，不是它们来适配界面。

**关于两档。** 第一档做一条能演示的链路，步骤和命令写全，照着做就能交。第二档两段都做：先照第一档完整走一遍，交付物与标准一条不减，再做第二段的增量——那一段撤掉步骤，只给目标、方向和验收标准。方向是**逐格可查证**：第一档的页面报出"准确率多少"，第二档的页面要能回答"这一格凭什么填这个数、那一格为什么空着"。对象是 01 那五百格加上 03 的该空格，不加新概念，也不多做文件。

**怎么算这周做成了？** 不看"页面好看"，看三件事：

1. 从选文件到看见那六个数，全程在浏览器里完成，中间不切终端、不打开 `/docs`。
2. 页面上任何一个数字，都能说清它是哪个接口返回的、那个接口又读了哪个文件。
3. 关掉页面重开，再走一遍，前五个数与上周一样、耗时同量级——页面没有偷偷改过任何数据。

三条都很朴素，但第 6 周别人接手时，第一件事就是照 README 把这三条走一遍。

**做完你应该看到**：六个数齐了（行数、写入格数、空着的格数、两个率、耗时），与上周那行对得上（耗时按量级对）；`data/eval_report.json` 能打开。对不上先别往下走——这周所有"页面上的数对不对"，都是拿它当参照。

### 第 1 步：把报告的形状定下来，让页面按名字取得到数

第 4 周没有规定这份文件的外层是数组还是对象，只规定了清单里每条有什么。本周把它定成对象——页面要按名字取值，数组取不到。

有一件事必须先说清：**这份文件是 `check_fill.py` 每次跑完写出来的。** 所以改在"写"的那一处，不要手改 JSON——手改的那份会在下次跑 `check_fill.py` 时被整个覆盖，而你可能两天后调页面时才发现数没了，还以为是页面读错。

改法：找到 `check_fill.py` 里写 `eval_report.json` 的那几行，把要写出去的内容按下面这张表组织。写之前先留个底：把现有文件复制一份（比如 `eval_report_prev.json`，放同一目录，别提交），改完用它比 `diff` 的条数。

页面要读的字段名，本周定成这些：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `doc` | 字符串 | 库里的文档名 |
| `rows` | 整数 | 填了多少行（这份文档是 100） |
| `cells_written` | 整数 | 实际写进去的格数（这份文档应当 500） |
| `cells_empty` | 整数 | 没填上的格数 |
| `cell_accuracy` | 小数 | 填对的格 ÷ 500 |
| `row_completeness` | 小数 | 五列全非空的行 ÷ 100 |
| `diff` | 数组 | 原来那份错格清单，一条不少 |

三条要求：

- **数值必须与第 4 周终端打印的一致**，一个不许变。你只是给它换了个容器，不是重算。
- **`diff` 的条数不变**，每条的内容不动。第 4 周已经定过每条含什么。
- **不要在这里重跑比对**。外层形状是"写"的事，不是"算"的事；为了凑字段名再跑一遍 `evaluate.py`，等于把第 4 周的两个率重算一次，风险与收益完全不对等。

**做完你应该看到**：用 python 读一次这个文件，能按名字取到 `cell_accuracy` 与 `row_completeness`，`len(diff)` 与第 4 周清单条数一样多；再跑一遍 `check_fill.py`，终端那行数字仍与第 0 步的一字不差。

### 第 2 步：后端加三个只读入口

只加三个，全部只读，不改第 4 周的任何逻辑。

| 路径与方法 | 入参 | 成功返回 | 它回答什么 |
| --- | --- | --- | --- |
| `GET /health` | 无 | `{"ok": true}` | 后端活着没有 |
| `GET /reports` | 查询参数 `doc`，库里的文档名 | 第 1 步那份报告的顶层字段 | 这份文档填得怎么样 |
| `GET /files` | 查询参数 `name`，`data/` 下的文件名 | 文件本身，浏览器下载 | 把填好的表交给用户 |

五条要求，每条都对应一个具体的失败：

- **`/reports` 只读文件，不重算。** 打开 `data/eval_report.json`，把顶层字段原样返回；读不到就 404 加一句人话（"这份文档还没有填写记录，先跑一次填写"）。不要在这里调 `evaluate.py`——那会读参考结果，也会让页面每刷新一次就跑一遍比对。
- **`/reports` 还要核对 `doc`。** 报告只有一份，里面记着它属于哪份文档。查询参数与它对不上时返回 404，不要原样返回——文档名写错时若照发，页面会安静地显示另一份文档的数，那正是"填错行"最像的样子。
- **`doc` 用查询参数，不要塞进路径。** 文档名是中文、还带后缀，放进路径要编码，漏一处就 404；查询参数交给框架处理，省事。
- **`/files` 必须挡目录穿越。** 这个入口按名字发文件，而名字来自浏览器，浏览器里可以填任何字符串。只放行同时满足三条的：取文件名之后与原名相等（不含路径分隔符）、以 `filled_` 开头、以 `.xlsx` 结尾；其余一律 400。**这不是洁癖**：不加这个检查，任何人敲一个 `?name=../.env` 就能把你的 Key 下载走。
- **文件不存在返回 404，不是 500。** 但这条不会自动成立：直接把不存在的路径交给 `FileResponse`，它会抛一个运行时错误，页面拿到的是 500。所以要先判断文件在不在，再决定返回文件还是 404；提示里带上你找的那个文件名，方便自查。

`/health` 看着多余，第 5 步就会用上：页面打开时先问一次，把结果写进顶部那行"后端状态"；之后每次操作前顺手再问一次，后端掉了就能立刻说清楚。**它能覆盖的只有这一种情况**——一开始后端就没起时，浏览器连 8000 都连不上，页面本身送不出来，你看到的会是浏览器自己的连接失败页，那不属于本页能处理的范畴。

**做完你应该看到**：`/docs` 里三个入口都在；`GET /health` 返回 `{"ok":true}`；`GET /reports?doc=输入_2025中国城市经济百强全景报告.docx` 返回两个率；`GET /files?name=filled_2025中国城市经济百强.xlsx` 触发下载；把 `name` 换成 `../.env` 返回 400。

### 第 3 步：用官方脚手架建前端，先 build 出一张空页

这周不手写 `index.html` 加一串 `<script>`，用 Vue 官方脚手架。**要认准是哪一个**：Vue 官方文档"创建一个 Vue 应用"那一节推荐的是 create-vue，它生成的项目已经配好 `.vue` 文件的编译；另有一个名字很像的 Vite 模板，也能建出 Vue 项目，但入口与目录不同，照本文对不上。本项目用 JavaScript，不用 TypeScript。

开工前先把 `frontend/` 里那个 `.gitkeep` 删掉——目录里只有它，删掉就是空目录，脚手架不会再问"目录非空、要不要覆盖"这种三选一。真被问了就选 **Ignore files and continue**，不要选 **Remove existing files**：那会清空目录，这次里面只有占位文件，但别养成这个手习惯。

在**仓库根目录**执行（不要在 `frontend/` 里执行，否则会得到 `frontend/frontend/`，后面每条路径都要多套一层）：

```

```

项目名填 `frontend`。接着会连着问一串可选项：TypeScript、JSX、路由、状态管理、单元测试、端到端测试、ESLint、Prettier、DevTools。**全部选 No**——路由不要（页面就一个）、状态管理不要（状态都在一个组件里）、测试与格式化工具不要（不是本周的事，装了只会多出一堆配置要读）。选项名与产物目录以官方文档那一页为准，对一遍再按回车。

问完先验一件最要紧的事：**建出来的必须是 JS 工程。** 判据只有两处——`src/` 下是 `main.js` 而不是 `main.ts`，根目录没有 `tsconfig.json`。新版脚手架在非交互模式下会默认带 TypeScript（`--default` 一次生成 TS 工程，且没有反向开关），所以不要图省事用一条命令跳过提问。真按 `--default` 建了也不用推倒重来：把入口改成 `main.js`、`vite.config.js` 重写成 JS 版，删掉 `tsconfig*.json`、`vue-tsc` 与 DevTools 相关依赖，最后对 `package.json`——它只该有 `vue`、`vite`、`@vitejs/plugin-vue` 三项。

装完先看 `node_modules` 在不在、`package-lock.json` 有没有生成；再看 `dist`。两步分开，出错时你才分得清是依赖没装上还是构建失败。**顺序不能颠倒**：`dist` 不存在时，下一步的挂载会让后端在启动那一刻就报错。

1. **重写 `src/App.vue`**：先只留一行字（比如"页面能打开"），把脚手架自带的欢迎页整段删掉。

### 第 4 步：把 dist 挂到后端，一个地址打开页面

在 `main.py` 末尾加一处静态目录挂载，把 `frontend/dist` 挂到 `/`。`StaticFiles` 从哪个模块导入，去 FastAPI 官方文档的静态文件那一页找；它有一个参数决定"访问目录时是否自动返回 `index.html`"，不开这个参数，打开 `/` 会 404。

三件事，每件都对应一个会让人查半天的现象：

- **挂载必须写在所有接口定义之后，也就是文件末尾。** 路由按注册顺序匹配，把 `/` 的挂载写在前面，`/parse`、`/extract`、`/fill`、`/reports` 会全被它先接住。表现不是清一色 404：静态服务不接 POST，三个 POST 接口会变成 **405**，而 `/reports` 这类 GET 变成 **404**——昨天还好，今天莫名其妙，两个不同的码让你以为是两个问题，其实是同一处写错了位置。
- **目录路径要能找得到。** 用 `__file__` 推绝对路径（`main.py` 的上一级、再上一级，拼 `frontend/dist`），比写 `../frontend/dist` 稳：后者只在"当前目录是 `backend/`"时成立，换个目录启动就 404。
- **`dist` 不存在时，`StaticFiles` 在启动那一刻就会报错**，整个后端起不来，连 `/docs` 都没有。所以启动前先看一眼 `frontend/dist/index.html` 在不在；不在就先 build，不要先起服务再回来查 404。这条要写进 README——第 6 周别人接手，第一件事就是它。

**做完你应该看到**：`fastapi dev main.py` 起来后（这个命令来自 `fastapi[standard]`；若你的环境里没有它，用 `uvicorn main:app --reload` 是同一件事），浏览器打开 `http://127.0.0.1:8000` 看到你写的那行字；`/docs` 仍能打开，三个接口的 Try it out 仍可用。**改完前端要重新 build 才看得到变化**——这一条从此刻起每次改页面都成立。

### 第 5 步：写 api.js，把接口包成几个函数

页面里不出现 `fetch`，也不出现接口地址——它们只在 `api.js` 里出现一次。

| 函数 | 入参 | 返回 | 对应接口 |
| --- | --- | --- | --- |
| `checkHealth()` | 无 | `{ok: true}` | `GET /health` |
| `uploadParse(file)` | 浏览器里的 `File` 对象 | 解析结果（`file` 与 `blocks`） | `POST /parse` |
| `uploadExtract(file, metrics)` | `File`、可选的指标清单 | `{count, kept}` | `POST /extract` |
| `runFill(doc, template)` | 文档名、模板名 | `{rows, cells_written, cells_empty}` | `POST /fill` |
| `readReport(doc)` | 文档名 | 第 1 步那份报告的顶层字段 | `GET /reports` |
| `fileUrl(name)` | 文件名 | 一个**字符串**地址，不发请求 | 交给 `<a href>` 下载 |

六个要点：

- **上传用 `FormData`。** `append` 的键名必须与后端表单字段一致（`/parse` 与 `/extract` 都收 `file`，指标叫 `metrics`），键名错了后端回 422，而页面只会显示"失败"。
- **不要手工设 `Content-Type`。** 用 `FormData` 时浏览器会自动带上含 boundary 的那个值；你手写成 `multipart/form-data`，boundary 就丢了，后端解析不出文件。
- **每个函数先判 `res.ok` 再取 JSON。** 后端出错时返回的是 4xx 或 5xx，不是 200；不判就会把一句错误当成功数据往下传，页面显示 `undefined`。
- **取 `detail` 要防一手。** 4xx 通常带 `detail`，但它不总是字符串——422 的 `detail` 是一个数组，逐条列出哪个字段不合格；500 的响应体可能根本不是 JSON。所以取不到就当没有，退回去显示状态码，别让"读错误信息"这一步自己再抛一个错。
- **错误要带上后端那句话。** 把 `detail` 取出来抛出去，页面才有东西可显示；"失败"两个字对排查毫无帮助。
- **网络层失败要单独接住。** 后端没起时 `fetch` 直接失败，抛出的是 `TypeError`，没有 `detail` 可取。所以每个函数外面要有一层 `try/catch`，把这种情况翻译成"后端没有响应"——否则页面上冒出来的是一句英文，而真正的原因（服务没开）一个字都看不到。

**做完你应该看到**：页面上有一行"后端状态"，打开时自动问一次，正常显示"后端在线"；**页面不要关**，把后端停掉，再点一次"重新检测"，这行变成"后端没有响应"。不要用刷新来试——刷新会连页面本身一起丢掉，你看到的是浏览器自己的错误页。

不要指望在浏览器 Console 里手动敲函数名来验——脚本模块里的函数默认不挂到全局，敲下去只会得到 `is not defined`。真要临时调，把它临时挂到 `window` 上，调完删掉。

### 第 6 步：第一块——文档入库

页面第一块负责"文件进来"。三个控件：文件选择框（`accept=".docx,.txt,.md"`——带点的扩展名写法才拦得住，写成 `docx` 不生效）、"解析"按钮、"抽取"按钮。

三个状态要摆对：

- **没选文件时，两个按钮都禁用。** 不禁用，用户点下去会收到一个"没有文件"的错，而这本来不该发生。
- **解析与抽取分开两个按钮。** 解析很快（这份 docx 一百多块，毫秒级），抽取是十几批、每批都要等模型回话，几分钟到十几分钟。合成一个按钮，等于每次解析都要陪跑十几分钟。
- **抽取中要有明确的等待提示。** 页面上写"抽取中，可能需要十几分钟，请不要关闭页面"，这期间按钮禁用。没有这句，人会以为页面死了，刷新一下——请求就断了。

文件输入框有一个坑：**`v-model` 对 `file` 类型不生效**，Vue 明确不支持——文件输入是只读的，官方错误码参考里有单独一条讲它，让你改用 change 事件。所以要用 `@change`，从 `event.target.files[0]` 取文件，存进一个 `ref`。

结构骨架如下，只搭架子、不写实现，两处 `TODO` 由你填：

```vue
<script setup>
import { ref } from 'vue'
import { uploadParse, uploadExtract } from './api.js'

const file = ref(null)
const blocks = ref([])
const count = ref(0)
const kept = ref(0)
const busy = ref('')      // '' | 'parse' | 'extract'
const error = ref('')

function onFileChange(e) {
  file.value = e.target.files[0] || null   // 用户点了取消时为空，要兜住
}

async function onParse() {
  // TODO：置 busy、清 error、调 uploadParse、把结果写进 blocks、finally 里复位
}

async function onExtract() {
  // TODO：调 uploadExtract，metrics 传这五个词（逗号分隔）：
  //   'GDP 总量,人均 GDP,常住人口,一般公共预算收入,人口'
  //   然后写回 count 与 kept；失败时把 detail 放进 error
}
</script>

<template>
  <section>
    <input type="file" accept=".docx,.txt,.md" @change="onFileChange" />
    <button :disabled="!file || busy" @click="onParse">解析</button>
    <button :disabled="!file || busy" @click="onExtract">抽取</button>
    <p v-if="busy">处理中，请勿关闭页面</p>
    <p v-if="error">{{ error }}</p>
    <p v-if="blocks.length">共 {{ blocks.length }} 块</p>
    <ul>
      <li v-for="b in blocks.slice(0, 5)" :key="b.locator.para ?? b.locator.line">{{ b.text }}</li>
    </ul>
  </section>
</template>
```

两处细节：`v-for` 的 `:key` 用块自己的位置，不要用数组下标——第 4 周那份 docx 的段落号本来就会跳号；docx 的 `locator` 是 `{"para": n}`、txt 与 md 是 `{"line": n}`，所以上面写成两个键兜着取。`{{ }}` 里不用写 `.value`，JS 里必须写——这条记住能省掉本周一半的排查时间。

**做完你应该看到**：选一份 docx，点"解析"，页面上出现块数（这份报告是 113）与前五块文字；点"抽取"，等一会儿出现抽出条数与可溯源条数。这两个数要与你第 4 周第 2 步跑同一份文件时相差不大——那一周用的清单就是 `GDP 总量`、`人均 GDP`、`常住人口`、`一般公共预算收入` 加一个 `人口` 兜底，本周的 `metrics` 照抄这五个词；差很多先查清单有没有变。

### 第 8 步：把链路串起来，留四样证据

**一、一键演示。** 页面顶部一个按钮，点下去按顺序走：解析 → 填表 → 读报告 → 显示六个数。**抽取不进这条链**——它要几分钟到十几分钟，演示时不能让人干等；它留在第一块的独立按钮里，需要时单独点。按钮按下后要显示当前走到哪一步（"正在解析…""正在填写…"）。链路上任何一步都可能卡住，没有这句，你会盯着一动不动的一分钟，不知道是慢还是死了。

一个取舍先说清：这条链要求先选文件（解析要用），但填表与读报告并不依赖那个文件——它们只要文档名。所以没选文件时按钮该禁用还是该允许空跑，你定；定了就在 README 里写一句，别让评审猜。

**二、三种坏情况的提示。** 三条都要在页面上真的试一遍，把提示原话抄进 README：

| 情况 | 怎么造 | 页面上应当看到 |
| --- | --- | --- |
| 后端没起 | **页面已经打开**，再停掉 `fastapi dev`，然后点"一键演示" | 顶部一句"后端没有响应，请先启动服务"，不是浏览器错误页 |
| 文档名写错 | 输入一个库里没有的名字 | "库里没有这份文档"这类话，不是 `undefined` |
| 没填过就看报告 | 换一个没跑过 `/fill` 的文档名，点"读报告" | "还没有填写记录"，不是 500 |

顺序别反：页面开着、后端在跑，只是页面先加载好了，这时停服务，页面还在，只是之后每次请求都失败——这才是能验出那句话的情形。若先关页面再停服务，再打开时浏览器连 HTML 都拿不到，你看到的是它自己的错误页，验不到你要验的东西。

**三、数字表进 README。** 一行：行数 / 写入格数 / 空着的格数 / 两个率 / 耗时（不含抽取）。再补一行环境：Node 版本、build 与启动命令。

**四、验证"改完要重新 build"这一条。** 把页面上某个字改掉（比如标题），先不 build，刷新 `8000`——页面没变；再 `npm run build`，刷新，页面变了。两次对比是本节的检查点：它证明你打开的是 `dist`，不是某个"看上去像"的旧文件。

两次刷新都用 `Ctrl+F5`（强制刷新）：浏览器会缓存 `index.html` 与其中的静态资源，普通刷新有时候拿到的还是旧文件，于是你以为是"没 build 成功"，其实是缓存。还有一点要放心：只改了前端、重新 build 之后，**不需要重启后端**——静态文件是每次请求现读的，不是启动时一次性载入的。

**做完你应该看到**：打开页面点一次"一键演示"，全程不切终端，最后六个数都在；三种坏情况各给出一句人话；改字 → build → 强制刷新这一组对比成立；README 里有那一行数字与三条提示原文。

# 第五周任务（第二档 · 挑战档）

第二档不是换个项目，而是同一条任务的第二层：第一段照第一档完整走完，第二段在没有可照抄步骤的前提下，把"页面有数字"升级成"每一格都说得出理由"。

两段都做。第一段不是重复劳动——它是第二段唯一的参照物：只有先让 01 那份的六个数站稳，你才有依据判断"加了逐格查证以后，原来那条链路有没有被改坏"。第二段只给目标、方向提示和验收标准，路径自己规划。选了第二档就按第二档交付：两段都做、都算数。

## 第一段：第一档本周任务

第一档第 0 步到第 8 步完整走一遍，交付物与通过标准一条不减。走完之后，手上应当有一条从选文件到下载的链路、六个数、三条坏输入的提示。第二段从这里开始。

## 第二段：增量任务

### 目标

让页面上的每一格都能被追问，并且答得出来。

第一档的页面向评审报告"准确率多少"。这一段要求它回答三个更硬的问题：**这一格填的是什么？这个数取自哪份文档、第几块、原话是什么？这一格为什么空着？**

对象是两份数据：01 那五百格，与第 4 周第二档 03 那份的一万七千多格。后者不是"顺便也接上"——01 本来就该填满，没有空格可解释；"空格必须有理由"这件事，只能在 03 上验证。默认你第 4 周已经按第二档做过 03（第二档要求两段都做）；如果你本周才升档、手上没有 03，就用 01 里"没取到数的那几格"去验"没有记录"这一类，并在 README 写明"拒填这一类本次不适用"——标准不变，能验的那部分照样要验。

三条约束，怎么实现都行，但必须守：

1. **第一段的产出不能被改坏。** 01 的五个稳定值（含两个率）、模板原件，与第一段一字不差。
2. **取详情只维护一处。** "按格取来源"这件事只写在一个地方；散进三处交互，改一次规则要对三遍。
3. **每一格都有结论。** 填过的有来源，空着的有理由；不接受"这一格空着，因为程序没跑到"。

### 难度在哪里

四件事，没有一件只是"多加一个面板"：

- **两份报告要按格子对齐，不是按城市。** 第 4 周已经说过键要用行号加列号。那会儿它是一条写法建议；现在它决定"点开这一格，取到的是不是这一格的记录"。用城市名对齐，一列写错位置就整片串位，而页面看起来正常。
- **规模不是一个量级，一格也不止一条信息。** 500 格与 17794 格差着 35 倍，每格还要展开四样：值、判定、来源、理由。全量铺开会卡，也会让人找不到要看的那一格。分页、按列筛、折叠、点开才取，选哪种都行——选完要能说清为什么，两份数据是否用同一种策略，也得有个理由。
- **"没记录"与"拒填"是两件事。** 程序没跑到的那一格，报告里没有它的条目；拒填的那一格，报告里有条目、理由归在某一类。前者是缺陷，后者是判断。界面上必须分得开——这是第 4 周"误填与漏填不能合报"在界面上的对应物。
- **两份数据的形状不同。** 01 的报告是"五百格里错的那几十条"，03 的是"一万七千格里差异的那些，加顶部四个量"。同一套格子详情要吃得下这两种形状；为 03 另起一个页面，等于承认前四周那套结构没立住。

还有一句要提前说清：**上面这些全是工程取舍，不是新概念。** 分页也好、折叠也好，都不用装新库、不用新的模型能力；本周的新概念仍然只有响应式一个。

### 方向提示

只给方向，不给路径。

- **先把"一格的身份"定下来。** 行号加列号够不够？03 那份还有日期列与国别，筛完之后行号还唯不唯一？这件事没定，后面所有"点开取详情"都是在猜。
- **详情面板的顺序值得想一遍。** 值、判定、来源、理由，哪个在前，决定了人是先看到"这格对不对"，还是先看到一段不知拿什么比的原文。
- **来源要能回到原始记录。** 填写报告里只有块号，原话在库里那张块表上；按文档名加块号去取。取法只写一处——写三处，第 6 周没人验得动。
- **验收时你是被抽查的人。** 给自己准备一张证据表，三格就够：两格填过的（一对一错），一格该空的。抽查的人不会按你的顺序挑。

### 通过标准

- [ ] 任意一个填过的格，点开能看到：填入值、判定（对/错）、来源文档名、块号、原话
- [ ] 原话与库里该块的文本一致（去空格后互相包含即可），不是从报告里另抄的一段
- [ ] 一个该空的格点开能看到拒填理由，且理由不是"程序没跑到"——03 那份有 330 个这样的格。若你手上没有 03，本项标注"不适用"，改用 01 的一格漏填去验"没有记录"那一类（它不叫拒填，见下一条）
- [ ] "没有记录"与"拒填"在界面上可区分（不同文案或不同标记），两种情况各举一例

# 卡住怎么办

**1、打开 `http://127.0.0.1:8000` 是 404 或一片空白。**

按顺序查三处：`frontend/dist/index.html` 在不在（不在就先 build）；挂载是不是写在 `main.py` 末尾（写在前面会把接口一起吞掉）；挂载用的目录路径是不是从 `__file__` 推出来的（写相对路径时，换个目录启动就找不到）。三处都对还是空白，按 F12 看 Console 里那条红色报错——通常是某个资源 404，说明 build 产物不全，重新 build 一次。

**2、改了变量，页面没变。**

这是本周最常见的一个。三个原因，从高频到低频：在函数里改的是普通变量（`let count = 0`），不是 `ref` 包着的那个；改了 `ref` 却在 JS 里忘了 `.value`（模板里不用写，JS 里必须写）；改的是从接口拿回来的对象里的某一层，而你没替换整个引用。判断办法很简单：在改完之后 `console.log` 一下那个变量，看它的值到底变没变——值没变是代码问题，值变了页面没变才是响应式问题。

**3、接口报错，页面只显示"失败"。**

按状态码分：404 是地址或参数名不对（`doc`、`name` 写成了别的）；405 是方法不对（把 GET 写成 POST）；422 是表单字段名与后端不一致（`file`、`metrics` 最容易写错）；400 是后端主动拒了，`detail` 里通常已经写了原因；500 是后端自己崩了，回终端看堆栈。**先看 Network 里那条请求的返回体**，再改代码——猜着改通常要改三遍。

**4、`fetch` 报 `Failed to fetch`，或者拿回来一段 HTML。**

两种可能：后端没起（终端里没有那行启动日志）；或者你打开的不是 `8000`（比如习惯性地点了开发服务器的地址）。这周只有一个入口，页面与接口同一个地址，出现"拿回 HTML"基本就是走错了端口。

**5、`npm` 报 `ENOENT ... package.json`，或者 Node 版本报错。**

前者是站错目录：`npm install` 与 `npm run build` 都要在 `frontend/` 里执行。后者是 Node 太旧：`node -v` 对一下官方要求的下限，不够就装当前 LTS，装完**关掉终端重开**——不重开，读到的还是旧版本。

**6、抽取点了很久没反应。**

它本来就是分钟级：十几批、每批都要等模型。先看页面上有没有"抽取中"的提示（没有就补上，这是本周要求的一部分）；再确认这期间你没有改后端代码——`fastapi dev` 的热重载会在你保存文件的那一刻重启进程，正在跑的请求直接断掉，表现是"点了很久，最后报错"。演示时不要一边改后端一边点抽取。

**7、30 分钟没有进展，就把三样东西整理好再问。**

"我点了什么、Console 里最后一条报错是什么、Network 里那一条请求的状态码与返回体是什么"。这三样凑齐，问题基本一眼能看出来；只贴一句"页面没反应"，谁也帮不上。这一周的 bug 大多不喊疼，只在你没看的地方留一行字。
